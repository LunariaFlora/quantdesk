# 实际 EXE 界面评审与迭代

日期：2026-10-05。回退点：b70f2b2。范围是已有历史研究桌面产品的五个页面及常见操作。

本次是单人模拟用户任务、实际界面操作、源码回归测试及打包验收；不是多人访谈或长期交易员研究。自己的 EXE 通过 Kimi Computer Use for Windows 在真实 Windows 窗口操作；外部产品对照依据官方界面资料，未登录并全面操作各家交易账户。

## 研究 → 实际复查 → 再修正的记录

1. 第一轮真实窗口评审：原版 PID 61056，窗口截图约 1568×988。查看首屏、运行回测、策略页；发现空白数据主区、裁切运行入口、图表覆盖、粗黑分隔条、整屏 JSON。
2. 根据三个官方产品的操作组织方式重排五页；把 JSON 从常用操作移到高级入口。
3. 小窗口渲染与行为测试发现，pyqtgraph 的 XLink 对宽度不同的面板按屏幕坐标连接，半宽资产图丢掉部分时间域。改为资产/回撤与价格图按精确日期范围双向连接。
4. 浅色渲染复查发现旧 KPI 与图例沿用深色文字。加入现有文本刷新、浅色曲线和主题记忆；图例刷新调用实际 setText，避免只更新选项而未重绘。
5. 最小尺寸测试发现图表最小高度之和仍大于剩余空间；QSplitter 分配高度不足导致重叠。缩减最小高度并将无重叠验证纳入测试。
6. 第二轮真实 EXE 操作：PID 28540，使用此数据回测→运行→将短周期 10 改为 5，旧结果明确标记；运行默认九组参数，自动同区间叠加，颜色对应表格。图例曾遮住多条曲线，因此移为表格名称前色块。
7. 本轮复查又发现状态栏按钮超出底边、参数研究没有标明当前策略。进一步调整状态栏控件高度，补充研究上下文与按策略切换扫描项。最终打包验收通过，见下面证据。

## 验证证据

`tests/test_ui_workflows.py` 检查自动选择、空筛选、参数与 JSON 同步、旧结果提示、配置恢复、成交定位、小窗口边界、图表无交叠、半宽日期联动、自动批量比较、不同区间反馈、主题/文字对比度和相关参数扫描。

全部测试还包含真实 AAPL 样本与独立 Backtrader 每笔成交及每日账本对照，界面重排不改变计算引擎。历史服务器测试仅测试保留的开发预览，不是正式桌面依赖。

最终版：36 项测试通过；Windows 打包成功；`outputs/ui-final-acceptance/acceptance.json` 中 `passed=true`、`packaged=true`，PID 32844 运行 506 根真实日线、8 策略比较和 9 组参数研究，保存恢复、账本恒等式、日期查询和六个导出文件通过，退出码 0。`desktop.png`、`comparison.png` 为最终 EXE 的原生窗口截图，已查看；`sockets.json` 六次存活采样的监听数均为 0。证据与行情、数据库、EXE 均保留在本机忽略目录。

最终交互复查 PID 92440：策略页表单可见，状态栏实际控件高度已缩到窗口内。随后窗口位置改变并被最小化，暂停界面输入以避免干扰人工查看；未用其他工具接管或绕过。深浅色切换、已有图例刷新及主题重启保留由源码窗口渲染与回归测试验证。

未解决的成熟产品差距：自定义规则的可视化构建、月度/年度绩效分析、热图、独立图表导出和自由工作区布局。实时账户、盘口、委托和多资产共享资金也尚未实现。这些差距与本次布局、反馈和常见研究流程修正分别记录，不把历史研究 EXE 称为实盘交易所。
